# Monitoring Spotify i Librespot — 12.10.2026

## Zakres i granice

Odczytowe monitorowanie bez uruchamiania AMC, Librespota, odtwarzania, logowania, testów konta, zmian zależności ani konfiguracji.

## Stan przypiętego hosta AMC

`native/AmcSpotifyLibrespotHost/Cargo.toml` przypina `librespot-core`, `librespot-playback` i `librespot-metadata` do rewizji `d36f9f1907e8cc9d68a93f8ebc6b627b1bf7267d` (v0.8.0). `Cargo.lock` potwierdza dla nich wersję `0.8.0` i tę samą rewizję.

Host nie ma kodu `Spirc`, discovery ani `ConnectConfig`; komentarz modułu w `native/AmcSpotifyLibrespotHost/src/main.rs:9` wprost opisuje brak discovery/Spirc. Wydaniowe rozszerzenia Connect w nowszym kodzie upstreamu nie zmieniają więc bieżącego działania AMC.

## Spotify Web API

Stan znany od poprzednich raportów pozostaje istotny: oficjalna referencja playlist oznacza pole `tracks` jako przestarzałe i wskazuje `items`. Aktualny AMC nadal tworzy adres `/playlists/{id}/tracks` w `src/AccessibleMediaController.Windows/Services/SpotifyApiClient.cs:310`; to istniejąca, zaplanowana do osobnego małego przyrostu niezgodność, nie zmierzona awaria konta.

Dostępne źródła nie ujawniły nowego październikowego wpisu changelogu. Zbiorcza strona zmian Spotify zwróciła błąd HTTP w tym odczycie, więc jest to brak pomiaru strony zbiorczej, a nie twierdzenie o braku zmian. Odczytane wpisy z lutego, marca i lipca nie wprowadzają nowej zmiany względem monitoringu z 05.10; lipcowe limity per konto dewelopera oraz odpowiedź `429` z `QUOTA_EXCEEDED` pozostają aktualne.

Termin ważności refresh tokenu (6 miesięcy, `invalid_grant` i wymagane ponowne logowanie) nie jest nowością tego tygodnia.

## Web Playback SDK i Lossless

Oficjalna referencja SDK nadal dokumentuje konstruktora z nazwą, tokenem i lokalną głośnością; nie dokumentuje wyboru urządzenia wyjściowego ani przełącznika/telemetrii Lossless.

Oficjalne wsparcie Spotify nadal podaje dla Web Playera Premium AAC 256 kb/s, bez możliwości ręcznej zmiany jakości. Lossless jest opisane dla Premium do 24-bit/44,1 kHz, nie dla podcastów, audiobooków ani teledysków; zależy też od zgodnego urządzenia i toru połączenia. To nie jest dowód jakości w AMC ani w SDK.

## Librespot

GitHub Releases nadal wskazuje v0.8.0 jako najnowsze wydanie, zgodne z przypięciem AMC.

Gałąź `dev` ma nieopublikowane zmiany: kolejkowanie przez Spirc, zdarzenie kolejki, poprawki połączeń (kolejne adresy dealera) i próbę kolejnego CDN po odpowiedzi innej niż 206. Nie wpływają na przypiętą rewizję AMC. Byłyby punktami do sprawdzenia przed świadomym podniesieniem silnika, razem z kompatybilnością łamiących zmian v0.8.0.

Issue #1583 pozostaje otwarte. Odczyt nie dostarczył nowego, opublikowanego wsparcia Spotify Lossless w Librespot.

## Wniosek

Nie ma nowej zmiany wymagającej automatycznej aktualizacji ani działania w AMC. Przed świadomą zmianą API/hosta nadal potrzebne są: biblioteka i playlisty (w tym `/items`), podcasty, logowanie z wygaśniętym odświeżeniem, play/pause/seek, kolejka, wybór wyjścia oraz NVDA. Dokumentacja i kompilacja nie byłyby dowodem odtwarzania.
