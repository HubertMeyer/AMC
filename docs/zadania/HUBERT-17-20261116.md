# HUBERT-17-20261116 — cicha aktualizacja AMC i opcjonalny dodatek NVDA

## Stan

16.11.2026: poprawka źródłowa oraz testy celowane są gotowe w izolowanym worktree. Nie zbudowano paczki wydaniowej, nie uruchomiono instalatora na instalacji użytkownika, nie instalowano dodatku i nie restartowano NVDA ani AMC.

## Zgłoszenia i zakres

- GitHub #17: cicha aktualizacja wersji alpha.510 wywołała pomocnik dodatku mimo braku `amcController`; jego błąd zamienił poprawną instalację AMC w kod 10 i zablokował automatyczny start.
- GitHub #14: launcher i updater muszą nadal odmawiać startu podczas zajętej blokady aktualizatora oraz chronić przed częściową podmianą.
- Zakres tej poprawki obejmuje wyłącznie cichy tor opcjonalnego dodatku AMC NVDA w `installer/AMC_Wx_Setup.iss` i `installer/update_amc_nvda_addon.py` oraz jego testy. Nie zmienia launcherów, updatera, protokołu dodatku, gestów ani zwykłego widocznego wyboru dodatku.

## Przyczyna źródłowa

`ShouldOfferAmcNvdaAddon` zwracało `True`, gdy `manifest.ini` dodatku nie istniał. `CurStepChanged(ssPostInstall)` używał tej funkcji także w trybie `WizardSilent`, więc próbował zainstalować dodatek nieobecny albo wcześniej odrzucony przez użytkownika. Pomocnik restartował NVDA po podmianie. Każdy jego niezerowy wynik ustawiało `PostInstallFailed` i rzucał wyjątek; mimo że AMC przeszło pełną kontrolę integralności i kontrolowany start, instalator zwracał kod 10, a updater nie wykonywał ponownego uruchomienia AMC.

## Uzasadnienie i decyzje

- Widoczny instalator nadal może pokazać dobrowolną propozycję dodatku przez `ShouldOfferAmcNvdaAddon`.
- Cichy instalator korzysta wyłącznie z nowej, węższej `ShouldSilentlyUpdateAmcNvdaAddon`: musi istnieć rozpoznawalny zainstalowany `amcController` o wersji starszej niż dołączona. Brak manifestu oznacza brak dodatku albo zachowaną wcześniejszą odmowę; cicha aktualizacja go nie instaluje.
- Pomocnik także odmawia instalowania brakującego dodatku. Dla istniejącej starszej wersji zachowuje kopię do odzyskania i podmienia tylko `amcController`, ale nie szuka NVDA do restartu i nie wywołuje restartu. Nowa wersja jest dostępna po następnym, świadomym uruchomieniu NVDA.
- Błąd opcjonalnej aktualizacji dodatku po udanej kontroli AMC zapisuje kod pomocnika do logu Inno Setup. Nie ustawia `PostInstallFailed`, nie rzuca wyjątku i nie blokuje integracji powłoki ani automatycznego startu poprawnie zainstalowanego AMC.
- Obecność starszego dodatku albo działającego drugiego profilu nie zatrzymuje całej aktualizacji AMC na etapie `PrepareToInstall`. Pomocnik nadal odmawia podmiany, gdy wykryje działający AMC, ale jego wynik pozostaje opcjonalny i zalogowany.
- Poprzednie zabezpieczenia #14 pozostają bez zmian: nowy launcher jest kopiowany przed runtime, launcher odmawia zwykłego startu przy mutexie aktualizatora, a updater przed podmianą zamyka komponenty bezpiecznie i po instalacji sprawdza pełny manifest.

## Materiał do dokumentacji użytkownika

Podczas cichej aktualizacji AMC nie instaluje dodatku AMC do NVDA, jeśli użytkownik go nie ma albo wcześniej go nie wybrał. Jeżeli użytkownik ma starszą wersję tego dodatku, AMC może zaktualizować tylko ten istniejący dodatek; NVDA nie jest wtedy samoczynnie restartowany. Zmiana dodatku będzie gotowa przy następnym uruchomieniu NVDA. Ewentualny problem z opcjonalnym dodatkiem nie cofa poprawnie zainstalowanej aktualizacji AMC ani nie powinien zatrzymać uruchomienia programu.
